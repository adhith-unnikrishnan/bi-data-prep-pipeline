# BI Data Prep Pipeline: blend, cleanse, enrich and model for Tableau / Power BI

An **Alteryx-style data preparation workflow in Python** that takes four messy source files from a
(fictional) 18-store UK retail chain and turns them into a **BI-ready star schema**: a DuckDB
database plus CSV/Parquet extracts that load straight into Tableau or Power BI.

> All data is synthetic and generated by `src/generate_raw.py` (seeded, reproducible).
> The mess is deliberate: it imitates what real source systems produce.

## The workflow

```
 store_master.csv ─┐  (Excel export: mixed-case IDs, padded city names)
 product_catalogue.json ─┤  (nested API JSON)
 pos_transactions.csv ─┤  (3 date formats, "£" prices, duplicates, bad quantities, missing SKUs)
 returns_log.txt ─┘  (pipe-delimited legacy file)
        │
   [Input] → [Data Cleansing] → [Unique] → [Filter] → [Join] → [Formula] → [Spatial Info] → [Output]
        │
   fact_sales ── dim_date · dim_store · dim_product · dim_channel   (+ semantic views in sql/views.sql)
```

| Alteryx tool | Where it happens here |
|---|---|
| Input Data / JSON Parse | `load_*` functions, `pd.json_normalize` for the nested catalogue |
| Data Cleansing / Select | trimming, casing, `£` stripping, label standardisation |
| Unique | duplicate re-sent rows removed |
| Filter | non-positive quantities, missing SKUs, orphan keys |
| Join (L/J/R outputs) | returns flagged on `txn_id + sku`; orphan checks on every dimension key |
| Formula | revenue, cost, gross margin, discount, UK fiscal year, bank-holiday flags |
| Spatial Info / Distance | haversine distance to nearest store, stores within 50 km, catchment type |
| Output Data | DuckDB tables + views, CSV and Parquet extracts, data-quality report |

## Data quality is logged, not hidden
Every rule writes to a data-quality log, which is published as [`docs/data_quality_report.md`](docs/data_quality_report.md).
In the default run, ~80.6k raw rows become **79.5k clean fact rows** after removing 798 duplicates,
142 impossible quantities and 234 rows with no SKU, and standardising ~7k inconsistent codes.

## Data model (built for BI use cases)
- **fact_sales**: one row per transaction line, with additive measures (revenue, cost, margin, discount)
  and the return flag
- **dim_date**: calendar + UK fiscal year (Apr–Mar), ISO week, weekend and bank-holiday flags
- **dim_store**: region and country, lat/long, store size, opening date, spatial catchment features
- **dim_product**, **dim_channel**
- **Semantic views** (`v_sales`, `v_store_month`) define measures once, so every dashboard agrees

See [`docs/connect_bi_tools.md`](docs/connect_bi_tools.md) for Power BI relationships and DAX measures,
and the Tableau relationship setup.

## Run it
```bash
pip install -r requirements.txt
python src/generate_raw.py      # writes raw/
python src/pipeline.py          # writes output/ (DuckDB, CSV, Parquet, DQ report)
python -m pytest -q             # integrity, reconciliation and parsing tests
```
